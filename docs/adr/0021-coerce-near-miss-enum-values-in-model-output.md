# 0021. Coerce near-miss enum values in model output instead of failing the generation attempt

- Status: Proposed
- Date: 2026-10-28
- Context: ADR 0013 makes the backend the validator of model output (model output is untrusted; backend assembles citations and enforces invariants) with a bounded retry for invalid output. Live observation (2026-10-28): `qwen2.5:3b` sometimes returns `"confidence": "NONE"` — a value outside the allowed `HIGH/MEDIUM/LOW/INSUFFICIENT_DATA` set — for questions it is uncertain about. Strict enum validation rejects the entire generation; after the single bounded retry the pipeline returns the generic controlled-error response, wasting a complete (and otherwise useful) generation. After ADR 0020 lowered the retrieval gate to 0.50, more borderline context reaches generation, so this failure class is more frequent. The same strictness applies to facet `status` and enrichment `action_type`, and enum matching is case-strict, so `"high"` or `"Answered"` also fail validation today.
- Decision: coerce near-miss enum values at the boundary where model JSON is parsed (`_GenerationSchema`), before the existing validation/invariant logic: (1) `confidence` is case-folded, with aliases `NONE`/`UNKNOWN`/`UNSURE`/empty mapped to `INSUFFICIENT_DATA` (semantically "no confidence"; IR-1..IR-6 remain intact because `INSUFFICIENT_DATA` forces `is_complete=false` and forbids uncited factual claims); (2) unknown facet `status` values map to `UNCERTAIN` (conservative: doubt is surfaced, never silently treated as ANSWERED — IR-2 still requires citations for ANSWERED); (3) unknown enrichment `action_type` values map to `ASK_USER` (most conservative suggestion). Valid values pass through unchanged. The bounded retry is unchanged and still covers non-enum failures (unparseable JSON, blank answers). The backend remains the single validator: coercion is normalization of untrusted input, not a relaxation of the invariants.
- Alternatives considered:
  - Prompt-only fix (stronger enum instructions) — rejected: a 3B local model will keep emitting near-miss values occasionally; the backend must stay robust to untrusted output.
  - Map `NONE` to `LOW` — rejected: `LOW` claims a citable answer exists; the model's intent when writing `NONE` is "no confidence", which is exactly `INSUFFICIENT_DATA`.
  - More retries (2-3 attempts) — rejected: retries spend another full generation (15-30s each) to fix a deterministic, mechanical problem; coercion is instant and lossless for valid output.
  - Drop fields with invalid enums (facet/suggestion) — rejected: silently losing facets hides uncertainty; conservative mapping preserves the model's signal.
- Consequences: recoverable generations now produce structured responses (usually `INSUFFICIENT_DATA` with the model's gap analysis) instead of generic controlled errors; fewer wasted retry rounds. Risk: an exotic invalid value is coerced rather than surfaced — mitigated because coercion targets only enum fields with conservative defaults, and the `retrieval_gating`/generation logs (now visible per the logging fix) still record raw attempts. If the model emits invalid enums for non-enum fields, the bounded retry still applies.
