# 0020. Recalibrate retrieval gate to 0.50 and disclose near-miss scores in gated responses

- Status: Proposed
- Date: 2026-10-28
- Context: ADR 0012 established threshold-gated dense retrieval with early exit, calibrated at 0.55. Live measurements on the running stack (2026-10-28, nomic-embed-text + Qdrant cosine) show answerable question phrasings scoring 0.52–0.84 against their evidence chunks: several natural phrasings of an answerable question (e.g. "what is the approved budget?" at 0.5469) fall below the 0.55 gate and are hard-rejected with `INSUFFICIENT_DATA` without invoking generation. Irrelevant queries (eval case_04) score 0.44–0.46. Embeddings were verified deterministic (cosine 1.0 between fresh and stored vectors, stable across model reloads), so this is a calibration problem, not embedding flakiness. Additionally, the `retrieval_gating` observability log promised by ADR 0012 exists in code but is invisible in practice because the app never configures logging (root logger stays at WARNING), and gated responses give no indication of how close retrieval came.
- Decision: (1) Lower the default cosine-similarity threshold from 0.55 to 0.50 (`retrieval_threshold` in `backend/app/config.py`; `RETRIEVAL_THRESHOLD` env override unchanged). The ADR 0012 mechanism — deterministic score gate with early exit, no generation on gated queries — is kept; only the calibrated value changes. The observed irrelevant band (≤ 0.46) stays rejected; the observed answerable band (≥ 0.52) is admitted; model-side invariants (citation-required validation, forced `INSUFFICIENT_DATA` on factual answers without valid citations) remain the second line of defense for tangential context admitted in the 0.50–0.55 band. (2) Gated `INSUFFICIENT_DATA` responses disclose the best retrieved score and the active threshold in `missing_info` (schema unchanged). (3) Configure stdlib logging so the existing `retrieval_gating` INFO lines and a document-processing INFO line (name + chunk count) are visible in application logs, keeping ADR 0012's observability promise.
- Alternatives considered:
  - Gap-based or dynamic gating (relative margin between top hits) — rejected: adds a second tuning parameter with no measured need; violates the project's simplicity rule.
  - Hybrid search (BM25 + dense) or reranking — rejected: ADR 0012 already rejects it as unmeasured scope growth.
  - Keep 0.55 and fix only logging — rejected: the false-rejection class reported by the user persists.
  - Lower below 0.50 (e.g. 0.45) — rejected: the irrelevant case_04 band (0.44–0.46) would start passing, trading a known false-rejection problem for false acceptances.
- Consequences: Answerable phrasings in the 0.50–0.55 band now reach generation (more generation calls; model must correctly abstain on tangential context — enforced by existing deterministic validation). False-acceptance risk in 0.50–0.55 is accepted and must be re-checked against eval cases (case_04 must remain gated). Threshold remains configurable; recalibration evidence is appended to `eval/CALIBRATION.md` (append-only). If the embedding model or chunking changes, the threshold must be recalibrated. This ADR refines the calibration of ADR 0012; it does not change the gating mechanism.
