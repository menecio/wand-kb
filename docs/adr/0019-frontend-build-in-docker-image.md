# 0019. Frontend built inside the Docker image (multi-stage backend Dockerfile)

- Status: Proposed
- Date: 2026-10-28
- Context: On a fresh clone `frontend/dist` is gitignored and nothing in compose builds it. `docker-compose.yml` bind-mounted `./frontend/dist:ro` into the backend container, but the backend only mounts it at `/` if `index.html` exists, so `docker compose up` left `/` at 404 and the UI never loaded. `README.md` promised `docker compose up -d` yielded the app at http://127.0.0.1:8000, which was false on a clean checkout.
- Decision: Build the frontend inside the Docker image with a multi-stage `backend/Dockerfile`. Stage 1 (`node:20-alpine`) runs `npm ci && npm run build`; stage 2 (`python:3.14-slim`) copies the built `frontend/dist` into the backend image at `/app/frontend/dist`. Compose uses `build: { context: ., dockerfile: backend/Dockerfile }` and removes the `./frontend/dist` bind mount. A root `.dockerignore` keeps the context lean. `README.md` documents `docker compose up -d --build` as the startup command. The same-origin design (backend `StaticFiles` at `/`) is unchanged.
- Alternatives considered:
  - Compose `frontend` build service (node image writing to shared bind mount before `app` starts) — rejected because it keeps host-artifact dependence, introduces start-ordering races, and writes back into the host workspace; still requires careful health/ordering wiring and doesn't give a reproducible pulled image.
  - Keep bind mount and document manual `npm ci && npm run build` on the host — rejected because it breaks the single-command promise and forces every reviewer/CI clone to have a matching node toolchain just to see the UI.
- Consequences: A fresh clone with only Docker can produce the full stack with `docker compose up -d --build`; the image is self-contained and pullable without host artifacts. Trade-off: frontend changes require `docker compose up --build` (image rebuild) in the containerized flow; the bind mount fast-iteration path is no longer wired by default (contributors doing active UI work use the documented `npm run dev` Vite path or can re-add a local bind-mount override via `docker-compose.override.yml`).
